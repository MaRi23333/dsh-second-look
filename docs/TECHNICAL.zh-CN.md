# 过目：使用与技术说明

[返回产品介绍](../README.md) · [English](TECHNICAL.en.md)

DSH `>=0.2.1-rc.5 <0.3.0-0` · Node.js `^22.19.0 || >=24.0.0` · `dsh-second-look@0.1.3`

## 工作机制

- **会话级两档审查**：在会话输入栏权限菜单中按会话选择档位，子代理沿用父会话的审查设置。切换档位后，当前会话和它的子代理中仍在进行的审批、之前缓存的放行结果都会失效。
  - **日常审查**（`Routine review`，预设 ID `second-look-daily`）：常规只读、新建普通文件和已验证空文件的普通写入按规则放行；已有非空文件的整文件覆盖送审，针对高风险删除、关键路径覆盖、可疑命令及明显凭据外传发起独立审查，单次审查最多执行 1 轮只读补证。
  - **加强审查**（`Enhanced review`，预设 ID `second-look-strict`）：在日常规则基础上检查文件差异（Diff）、脚本内容、网络外传与持久化动作，单次审查最多执行 3 轮只读补证，并在执行前及交付前按文件批次核对代码修改。
- **用户自配独立审批模型**：审批模型由用户在设置中显式配置（`reviewerModelProvider` 与 `reviewerModel`，可选配思考强度 `reasoningEffort`），不会回退到当前主工作模型。加强档可单独配置审批路由，留空时复用基础设置。模型凭据由 DSH 宿主统一管理，插件本地设置文件不保存 API 密钥。审批输出限定为四类裁决：`allow`（放行）、`ask_user`（转宿主人工审批）、`deny`（拒绝）、`need_evidence`（请求只读补证）。
- **一次放行只对一次调用有效**：每次放行结果与执行令牌、调用 ID、会话 ID、工具名称、参数摘要及配置版本绑定，只能使用一次。如果执行时参数变了，或者重复使用同一次放行结果，插件就会拦截。
- **语言跟随宿主**：客户端设置界面、会话权限菜单、审批提示、拦截说明与交付汇总均跟随宿主当前界面语言（简体中文 / 英文）切换。
- **送审脱敏与出站检查**：发往审批模型的参数、上下文和差异证据会对命中规则的敏感片段做 `[REDACTED]` 替换；启用门控会话的出站模型请求同样经过已知凭据特征检查，未获披露授权的原始请求不会直接发出。

## 本地构建与开发试用

桌面用户可按[首页安装步骤](../README.md#开始试用)直接安装预编译插件。下面的构建步骤供修改源码的开发者使用。

### 1. 安装依赖与构建检查

进入插件源码所在目录后执行：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

日常开发可同时运行 `pnpm lint` 检查代码规范。源码目录包含 `cordis.patch.yml`（声明插件 ID `dsh-second-look`）及品牌资源（横幅 `assets/readme/hero.png`、图标 `assets/brand/logo.png`）。

### 2. 本地挂载与模型配置

0.1.0 统一采用新命名，不读取或迁移旧 `gate-check` 设置、历史及会话档位；请作为新插件安装并重新选择审批模型与会话档位。

1. **挂载插件**：通过 DSH 插件管理器从该本地插件目录安装或建立开发链接（无需手工拼写或直接改写宿主现有 `cordis.yml`）。
2. **选择审核模型**：打开宿主客户端「**设置 → 过目**」，在「**审核设置**」页签中从宿主模型目录选择或手动填写 `reviewerModelProvider`（服务商）与 `reviewerModel`（模型），按需设置思考强度及补证超时预算。服务商 API 凭据请在宿主自身的模型服务设置中配置。保存后设置会写入本地 `$DSH_HOME/second-look/settings.json`。
3. **确认插件已启用**：在会话输入栏底部的权限菜单中选择「**日常审查**」或「**加强审查**」，让 AI 读取一个文件，然后打开「**设置 → 过目 → 审批记录**」查看是否出现对应事件记录。该步骤仅用于确认插件挂载与记录写入正常，不代表审批模型的判断准确率。

## 审批记录与交付前核对

### 审批记录留存

「**设置 → 过目 → 审批记录**」提供两个记录视图，支持按工具名称、理由、会话 ID 或调用 ID 搜索与筛选，并支持导出脱敏 JSON 或清空当前分类记录：

- **最近记录**：在内存中保留本次运行最近的 **500** 条审批事件，宿主重启后清空。
- **拒绝与拦截**：最近 **100** 条拒绝或拦截记录单独存在 `$DSH_HOME/second-look/blocked-audit.json`，重启后也能查看。正常放行的操作不占这 100 条。

### 交付前汇总工具 `second_look_finalize`

在**加强审查**档位下，智能体可在任务交付前调用 `second_look_finalize` 工具，按当前文件内容哈希重新盘点本轮变更并输出四类状态：

- **已审查（`reviewed`）**：当前内容与最近一次有效批次审查哈希一致的文件。
- **待审查（`pending`）**：尚未经过有效批次审查，或审查后再次发生变动的文件。
- **人工放行（`userAllowed`）**：经宿主人工审批明确允许的单次操作记录。
- **覆盖缺口（`gaps`）**：二进制文件、超出比对大小或数量预算的文件、已删除文件或未受 Git 跟踪的改动。

宿主目前没有拦截最终文本回复的会话结束钩子，`second_look_finalize` 依赖智能体主动调用，不能阻止智能体直接输出最终回复文本；因此智能体完成回复并不等同于所有代码变更已通过审查。

## 哪些情况可能拦不住？

1. **非操作系统沙箱**：插件运行在 DSH 应用与工具调度层，不具备操作系统或内核级沙箱隔离能力；插件未挂载或被禁用时，会话回落至宿主原有权限逻辑。此外，审批针对调用发起时的参数与文件快照，无法消除审批完成至实际执行之间的外部并发修改窗口。
2. **模型存在误判，真实环境准确率尚未全面验收**：审批结论依赖所选语言模型的推理表现，实际使用中可能出现误报（拦截正常操作）或漏报（放过混淆、隐蔽的危险操作）。现有自动化测试验证的是插件状态流转、规则匹配与调度守卫，真实宿主升级流程及真实审批模型的判断准确率尚未完成全面验收。
3. **未覆盖所有 I/O 路径**：只有启用审查的会话才会检查交给 DSH 调度的工具调用。直接通过 Node 读写文件、适配器自行联网、第三方插件自己读写数据，以及未启用审查的会话，都不在检查范围内。
4. **`second_look_finalize` 依赖协作调用且按单文件复核**：如上所述，`second_look_finalize` 不能阻止最终文本输出；其批次复用按单文件内容哈希核验（受文件数量与单文件体积预算限制），不会对多个已审文件形成的新交互组合自动做跨文件重审。
5. **敏感内容检测有限，出站人工授权 UI 尚缺**：敏感内容扫描基于有限的已知特征规则（如常见私钥块、特定前缀 API Token、JWT、Bearer 令牌、`KEY=VALUE` 键值等），无法识别所有秘密格式、自然语言敏感信息或编码混淆内容；附件正文在出站钩子之后载入，不在出站扫描范围内。对于命中规则的内容，并非一律自动转交人工弹窗：工具调用层面的 `ask_user` 会转交宿主审批界面，而出站模型请求层面目前尚无独立的人工授权 UI——命中未授权敏感内容时会阻断原始请求发送，仅在本地脱敏复扫通过时以脱敏副本继续会话，否则直接返回拦截错误；若送审请求自身在脱敏后仍命中敏感规则，该送审请求也会被直接阻断而不递归发起隐私审核。
6. **环回设置接口无访问令牌**：本地设置与审计 HTTP 接口（`/second-look/*`）绑定环回地址并校验 `Host` / `Origin` 以阻止浏览器跨域请求，但未设置访问令牌，不防御同一本机上的其他进程访问或修改插件设置。
7. **额外延迟与 Token 开销**：独立模型审查与多轮自动补证会增加工具执行的等待时间，并产生额外的模型 Token 消耗。
